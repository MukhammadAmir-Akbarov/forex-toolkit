# Security Policy

## Поддерживаемые версии

| Version | Supported |
|---------|-----------|
| 0.1.x   | ✅ |
| < 0.1   | ❌ |

## Как сообщить об уязвимости

### Что мы считаем уязвимостью

- **Утечка секретов**: API-токены, пароли, ключи в коде или истории git
- **Опасные команды**: bash injection через user input в Python-инструментах
- **Сторонние зависимости** с известными CVE
- **Финансово-критичные баги**: ошибка в калькуляторе позиции, которая ВСЕГДА считает риск меньше планового → пользователь рискует больше денег, чем думает
- **XSS** на сайте (mkdocs страницы с пользовательским вводом)

### Что НЕ уязвимость

- Стратегия не приносит прибыль — это не баг, это рынок
- Брокер не разрешает 0.01 лот — это политика брокера
- Сайт показывает русский на странице `/en/` для не-переведённых страниц — это fallback, by design

## Канал репортинга

**Не открывайте публичный issue** для уязвимостей.

Используй один из:

1. **GitHub Security Advisory** (приватный) — [Report a vulnerability](https://github.com/MukhammadAmir-Akbarov/forex-toolkit/security/advisories/new)
2. **Email через GitHub-профиль** — найди мою контактную информацию на [@MukhammadAmir-Akbarov](https://github.com/MukhammadAmir-Akbarov)

### Что включить в репорт

- Чёткое описание проблемы
- Шаги воспроизведения
- Версия / коммит, где найдено
- Возможное воздействие
- Предложение по исправлению (опционально)

## Сроки

| Этап | Срок |
|---|---|
| Подтверждение получения | 48 часов |
| Первичная оценка | 7 дней |
| Исправление критичных уязвимостей | 30 дней |
| Раскрытие после fix | 90 дней (или раньше по согласованию) |

## Признание

После публичного раскрытия твой ник будет указан в release notes исправляющей версии (если ты не против).

## ⚠️ Дисклеймер по финансовой безопасности

Этот проект — **образовательный**. Никакие материалы не являются финансовым советом. Если ты обнаружил **ошибку в расчёте**, влияющую на торговые решения пользователей, — **сообщай через Security Advisory с пометкой `[FINANCIAL-CRITICAL]`**. Такие репорты приоритетные.
