# Мутационное тестирование финансового ядра

Обычные тесты проверяют код. Мутационные проверяют **тесты**: инструмент
портит код специально — меняет `>` на `>=`, знак, `break` на `return`, — и
смотрит, покраснеет ли хоть один тест. Если не покраснел, значит эта строка
формально покрыта, но фактически не проверена.

Для этого проекта проверка стоит дороже среднего: ошибка в `fx_math` — это
неправильный размер позиции у человека, который торгует на свои.

## Что мутируем

Только два модуля, где ошибка стоит денег пользователя:

- `forex_toolkit/fx_math.py` — размер пункта, стоимость пункта, расчёт лота;
- `forex_toolkit/risk_budget.py` — лимиты риска, серия убытков, дневной и
  недельный бюджет.

Настройка — в `pyproject.toml`, секция `[tool.mutmut]`.

## Как запустить

```bash
.venv/bin/pip install -e ".[mutation]"
.venv/bin/mutmut run          # ~10 секунд, 159 мутантов
.venv/bin/mutmut results      # список выживших
.venv/bin/mutmut show forex_toolkit.fx_math.x_calc_lots__mutmut_14   # что именно подменили
```

`mutmut` копирует проект в `mutants/` (в `.gitignore`) и гоняет там pytest.

## Почему тесты выбраны, а не все подряд

`pytest_add_cli_args_test_selection` перечисляет ровно два файла:
`tests/test_fx_math.py` и `tests/test_risk_budget.py`. Причина техническая:
остальные тесты импортируют инструменты из `tools/` по голому имени (это
делает `tests/conftest.py`), а в копии `mutants/` соседних каталогов нет —
сборка падает ещё до первого мутанта.

Побочный, но полезный эффект: оба файла проверяют **пакет напрямую**, а пакет
и есть публикуемый артефакт. До этого `fx_math` тестировался только через
обёртки в `tools/`.

## Что нашёл первый прогон (2026-08-09)

159 мутантов, **26 выживших** — то есть каждая шестая подмена оставалась
незамеченной. Самые дорогие:

| Подмена | Чем грозила |
|---|---|
| `after_percent > limit` → `>=` | Риск ровно по лимиту требовал бы лишнего подтверждения на каждой сделке |
| `result_r >= 0` → `> 0` | Сделка в безубыток считалась бы убытком: пауза после трёх нулей |
| `result_r >= 0` → `>= 1` | Прибыль +0.5R не прерывала бы серию убытков |
| `break` → `return` | Серия убытков превращалась бы в `None` при любой победе в истории |
| `pip_value <= 0` → `<= 1` | Микро-лот (0.1 USD за пункт) — самый частый случай новичка — переставал считаться |
| `raw * 100` → `raw * 101` | Лот округлялся вверх: риск выше запланированного при правдоподобном числе |
| `max(0.0, …)` → `max(1.0, …)` | При исчерпанном лимите рисовался бы целый R запаса, которого нет |

Все закрыты тестами; сейчас **159 из 159 убито**. Гейт в CI держит этот
результат: новая строка в этих двух модулях обязана прийти с тестом, который
падает при её подмене.

## Если гейт упал

Смотри, какой мутант выжил (`mutmut results` → `mutmut show <имя>`), и
спроси себя: *какой ввод отличает настоящий код от подменённого?* Обычно это
граница — ровно лимит, ровно ноль, значение между 0 и 1. Такой тест и надо
дописать. Ослаблять гейт не нужно: он про два файла, а не про весь проект.
