## Tier 0 — Защита вложенного (фундамент, максимальный рычаг)

### I1. Детектор дрейфа переводов · P0 · M · maint: none после настройки
**Проблема (факт).** `tools/check_translation_coverage.py` проверяет только *наличие*
`.en.md`/`.uz.md`, но не *свежесть*. Правишь RU-страницу → UZ/EN молча устаревают, CI зелёный.
На 177 файлах это главный скрытый риск.
**Решение (Option A — манифест, рекомендуется).**
- Добавить `tools/i18n-manifest.json`: на каждый RU-файл `ru_sha256` + по локали `{sha_of_source_at_translation_time, verified_at}`.
- Добавить `tools/check_translation_drift.py` (~100 строк): пересчитать sha256 RU, сравнить с тем, под который делали перевод; если разошлось — флаг «перевод устарел».
- Добавить `tools/update_translation_manifest.py` — обновляет запись после перевода.
- В `.github/workflows/test.yml` (job `docs`) добавить шаг после coverage; сначала **informational**, потом blocking при `lag > N`.
- Backfill: один прогон проставит текущие sha для всех 59×2.
**Альтернатива (Option B).** sha источника во frontmatter каждого перевода — проще, но «шумит» в файлах.
**Готово, когда:** правка любого RU-файла без обновления перевода роняет (или предупреждает) CI с точным списком устаревших страниц.

### I2. Рефакторинг виджетов: общий JS + словари строк · P0 · L · maint: −−− (сильно снижает)
**Проблема (факт).** 10 интерактивных виджетов, ~2273 строки JS, **60–80% дублируется**
по 3 локалям (напр. risk-of-ruin 334×3, flashcards 412×3). Багфикс в финрасчёте надо вносить
трижды; копии уже расходились (ловили `ru-RU` локаль, битые места). Математика идентична,
отличаются только строки UI и параметр `toLocaleString`.
**Решение.**
- Вынести логику в `_mkdocs/javascripts/widgets/<name>.js` (10 файлов, 0 хардкод-строк).
- В каждом `.md` (RU/EN/UZ) оставить только контейнер `<div>` + `window.WIDGET_STRINGS = {…}` (подписи) + `<script src=…>`.
- Начать с **одного** виджета (margin-calculator — простой) как пилот, проверить i18n-пути `../javascripts/widgets/…` на `/`, `/en/`, `/uz/`.
**Риски (из разведки).** Разрешение путей в mkdocs-static-i18n; CSP для внешних скриптов; порядок загрузки DOM. Митигировать пилотом + сохранить fallback.
**Готово, когда:** правка формулы в одном `.js` отражается на всех трёх локалях; `mkdocs build --strict` зелёный; виджет работает на всех языках.

> ✅ **СДЕЛАНО (расчётные калькуляторы).** Вынесены все 7 калькуляторов с
> математикой: `margin`, `compound`, `pip`, `position`, `winrate`, `tax` (+ общий
> `_i18n.js` с `window.FXW`). Локаль берётся из `<html lang>`, а не из путей —
> риск путей i18n снят: скрипты грузятся глобально через `extra_javascript`,
> каждый виджет сам проверяет свой контейнер. Реализация отличается от исходного
> плана (строки лежат в самом `<name>.js` таблицей по локали, а не в
> `window.WIDGET_STRINGS` внутри `.md`) — так нет дублирования строк в трёх `.md`.
> Попутно закрыты 3 бага копий: `compound` markdown `**` вместо `<strong>`,
> `pip`/`position` — неверная локаль `toLocaleString` в UZ-копиях.
> e2e (I3) расширены до 9 кейсов, включая кросс-локальные.
>
> **Намеренно НЕ вынесены** контент-виджеты с `localStorage` и большим объёмом
> локализованного текста (`flashcards`, `quiz`, `progress`, `pre-trade-check`,
> `withdrawal-guide`): там нет общей **математики**, только переведённый контент —
> вынос дал бы гигантскую таблицу строк при около-нулевой выгоде «фикс в одном месте».

### I3. Playwright-тесты виджетов · P1 · M · maint: low
**Проблема (факт).** 8+ виджетов считают **реальные деньги без единого теста**; Python покрыт на ~98%, JS — слепая зона. С утроением копий риск расхождения вырос.
**Решение.**
- `tests/e2e/` + `playwright`; `mkdocs serve` в CI, фикстуры JSON с эталонами из `forex_toolkit/fx_math.py`.
- Тестируемы (детерминированы): position, pip, margin, compound, winrate-rr. risk-of-ruin — проверка стохастических границ. flashcards/quiz/progress — только UI-взаимодействие.
- Отдельный CI-job (может быть non-blocking сначала).
**Синергия:** после I2 тестируешь **один** модуль на виджет, а не три.
**Готово, когда:** ввод табличных кейсов в браузере даёт те же числа, что Python-эталон; job в CI.
